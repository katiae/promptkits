# AI design system generator

Every template gets its own design system — same structure, look and features as Halyard — generated by AI from the template's HTML and prompt, then reviewable from the admin page.

## What you'll see

- **Admin page:** a "Generate design system" button on each template (also offered automatically right after saving a new template with HTML). It shows progress, then a "Ready" state with "Preview" and "Regenerate".
- **Visitors:** nothing changes in the flow — the Design System button appears on any template that has one; signed-out visitors see the sign-in teaser, signed-in visitors get the guidelines page, full-screen view, Dark/Light switch and ZIP download.
- **Halyard stays exactly as it is** (hand-built files win over generated ones).

## How the generator works

1. **Read the template.** The template's HTML is condensed (its CSS, colours, fonts, radii, spacing, animations and a sample of the markup) and sent with the prompt.
2. **AI writes a structured spec, not raw files.** It returns one strict JSON "design brief" following the Halyard schema:
   - brand: name, short prefix (e.g. `hy`), voice, one-line overview
   - fonts: display / body / mono + Google Fonts link
   - tokens for **both dark and light** themes: surfaces, text, lines, accent (with AA-safe light variant), status colours, radii, spacing scale, shadows, motion durations and easings
   - per-component notes (purpose, do/don't, variants) for the full fixed component list
3. **Code builds the package from that spec**, so every system is complete and consistent no matter what the AI returns:
   - `index.html` guidelines page — same sidebar groups (Foundations, Navigation & controls, Forms & inputs, Feedback & status, Data & content, Motion & patterns), visible component titles, live specimens, token tables, coordinate scroll spy, and the Dark/Light message bridge
   - `tokens/tokens.css` + `tokens.json` (both themes)
   - `dist/<prefix>.css` component styles driven only by tokens
   - `react/*.tsx` components + matching `*.stories.tsx` for Storybook
   - `guidelines/brand.md` + one `guidelines/components/<Name>.md` per component
   - `README.md` with install steps for GitHub and Storybook
4. **Fixed component list** (always included): Button (sizes + variants), TextField, Select, Checkbox, Radio, Switch, DatePicker, SegmentedControl, Tabs, CommandMenu, Pill, Tag, Avatar, Kbd, Card, Table, Accordion, StatusIcon, PriorityIcon, ProgressBar, Reveal, Marquee.

## Technical details

- New table `design_systems` (entry_id unique, files jsonb, spec jsonb, status ready/generating/failed, error, updated_at). Admin-only writes via `has_role`; **no anon/public read** — files are served only through the existing signed-in server functions, keeping the paid-ready content private.
- `src/lib/design-system.server.ts`: bundled repo files first, then DB fallback; `listDesignSystems` merges both.
- `src/lib/ds-generator/` (server-only): `spec.ts` (zod schema + strict JSON schema), `condense.ts` (HTML → compact style summary), `render/*.ts` (pure functions spec → files).
- `src/lib/design-system-gen.functions.ts`: admin-checked server fn calling the AI Gateway (`openai/gpt-6-astra`, Responses API, streamed, strict json_schema, reasoning medium), validating/clamping the spec, rendering files, saving the row. Errors (credits, rate limit) shown in the admin UI; no auto-retry.
- Admin UI wired in `_authenticated/admin.tsx`; preview reuses the existing design-system route.
- AGENTS.md rule added for the spec-then-render approach.
